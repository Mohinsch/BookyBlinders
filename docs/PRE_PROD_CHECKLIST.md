# Pre-Production Checklist - Booky Blinders

**Owner:** Mohinî Schirinzi
**Last updated:** May 2026
**Scope:** Verifications to perform **before** every merge to `main` (which triggers an automatic production deployment to Vercel).

This checklist must pass entirely before the release manager (currently the project owner) approves a Pull Request into `main`.

---

## 1. Code quality & automated checks

These steps are enforced by the CI-Prod pipeline (`.github/workflows/ci-prod.yaml`). The PR cannot be merged if any check is red.

- [ ] **Linting** (`npm run lint`) — Biome reports 0 errors and 0 warnings.
- [ ] **Unit tests** (`npm run test`) — all Vitest suites pass.
- [ ] **Coverage threshold** — global coverage on `src/actions`, `src/services`, `src/lib` stays above **90%** (configured in `vitest.config.ts`).
- [ ] **Type checking** — `tsc --noEmit` succeeds (executed implicitly via `next build`).
- [ ] **Build** — `npm run build` produces a clean Next.js production bundle.

## 2. Database migrations

- [ ] If the schema changed, a new migration file exists in `src/db/migrations/` (generated by `npm run db:generate`).
- [ ] The migration file has been **manually reviewed** for destructive operations (DROP COLUMN, DROP TABLE, NOT NULL on existing columns without default).
- [ ] The migration has been tested locally against the Docker database (`npm run db:push`).
- [ ] If the migration is **non-reversible** (data loss possible), a Supabase backup has been triggered manually before merging — see [ROLLBACK.md](./ROLLBACK.md) §3.
- [ ] No raw SQL hand-edited inside the migration file (use Drizzle schema changes instead).

## 3. Security & secrets

- [ ] No `.env`, `.env.local`, credentials, or API keys committed (verified via `git diff --stat`).
- [ ] If new environment variables were introduced:
  - [ ] Added to `env.example` with a placeholder value.
  - [ ] Configured in Vercel (Production scope).
  - [ ] Configured in GitHub Secrets if needed by CI.
- [ ] `npm audit --omit=dev` reports 0 high or critical vulnerabilities (see [SECURITY_AUDIT.md](./SECURITY_AUDIT.md) §9).
- [ ] No `console.log` containing user data, tokens, or secrets in production code paths.

## 4. Smoke tests on Vercel preview deployment

Every PR triggers a Vercel preview build with a unique URL. Manually verify the following on that preview before merging:

### 4.1 Public pages (non-authenticated)

- [ ] **Home (`/`)** — loads, hero section visible, random books displayed.
- [ ] **About (`/about-us`)** — loads, content rendered.
- [ ] **Privacy (`/privacy`)** — loads.
- [ ] **Terms (`/terms`)** — loads.
- [ ] **404** — visiting a non-existent route shows the custom not-found page.

### 4.2 Authentication flow

- [ ] **Register (`/register`)** — creating a new account with valid credentials succeeds and redirects to `/library`.
- [ ] **Register validation** — submitting invalid email / weak password shows server-side error messages.
- [ ] **Login (`/login`)** — logging in with the freshly created account succeeds.
- [ ] **Login error** — wrong password shows error and stays on `/login`.
- [ ] **Session persistence** — refreshing the page keeps the user logged in.
- [ ] **Logout** — logout clears the session and redirects to `/`.

### 4.3 Authorization (access control)

- [ ] **Protected routes** — visiting `/library` while logged out redirects to `/login`.
- [ ] **Protected routes** — visiting `/account` while logged out redirects to `/login`.
- [ ] **Cross-user isolation** — the books / libraries shown belong only to the logged-in user (no data leak between accounts).

### 4.4 Core feature: book management

- [ ] **Search** — searching for "Harry Potter" returns results from Google Books with cover images.
- [ ] **Empty search** — submitting an empty query shows a user-friendly message (no crash).
- [ ] **Book detail (modal)** — clicking a result from inside the app opens the book modal (intercepting route).
- [ ] **Book detail (full page)** — refreshing the modal URL loads the full book page (`/books/[id]`).
- [ ] **Add to library** — adding a book persists in the database and appears in `/library`.
- [ ] **Update reading status** — changing status (`To read` → `Reading` → `Read`) updates and persists.
- [ ] **Delete book** — removing a book from the library updates the UI and the database.

### 4.5 Account & GDPR

- [ ] **Change password** — entering current + new password succeeds, old password is rejected on next login.
- [ ] **Delete account** — entering correct password deletes the account; logging in afterwards fails ("user not found").
- [ ] **Cascade deletion** — verify in Supabase that no orphaned rows remain in `library`, `library_book`, or `session` for the deleted user.

### 4.6 UI / accessibility / responsive

- [ ] **Mobile (iPhone SE viewport, 375px)** — header burger menu works, no horizontal scroll, touch targets ≥ 44px.
- [ ] **Tablet (768px)** — layout adapts correctly.
- [ ] **Desktop (1440px)** — full layout renders.
- [ ] **Dark mode** — toggling theme works, no white flash, no unreadable text.
- [ ] **i18n** — switching FR ↔ EN updates all visible strings, no missing keys.
- [ ] **Keyboard navigation** — all interactive elements reachable via Tab, focus visible.
- [ ] **Modal focus trap** — opening a book modal traps focus inside; Escape closes it.

### 4.7 Performance & SEO

- [ ] **Lighthouse Performance** ≥ 85 on home and `/library` (mobile profile).
- [ ] **Lighthouse Accessibility** ≥ 95.
- [ ] **Lighthouse SEO** ≥ 95.
- [ ] **Page weight** — initial JS bundle on `/` stays under ~200kB gzipped.
- [ ] **No console errors** in the browser DevTools on any tested page.

### 4.8 Security headers

- [ ] Run `curl -I https://<preview-url>/` and confirm the 6 security headers from [SECURITY_AUDIT.md](./SECURITY_AUDIT.md) §7 are present.
- [ ] No CSP violation logged in the browser console while navigating the app.

## 5. External services health

- [ ] **Supabase** — database is reachable, no active incident on https://status.supabase.com.
- [ ] **Vercel** — no active incident on https://www.vercel-status.com.
- [ ] **Google Books API** — quota usage below 80% of daily limit.

## 6. Rollback readiness

- [ ] [ROLLBACK.md](./ROLLBACK.md) procedure has been re-read by the release owner.
- [ ] The previous Vercel production deployment is identified and known to be stable (used as rollback target if needed).
- [ ] If a database migration is part of this release, the corresponding rollback migration is documented in the PR description.

## 7. Communication

- [ ] PR description mentions:
  - Summary of changes (1–3 bullets).
  - Risk level: low / medium / high.
  - Whether a database migration is included.
  - Whether new environment variables are required.
- [ ] If the release introduces a breaking change, external testers (Arthur, Jonas, Nicolas, Jonathan) have been notified.
